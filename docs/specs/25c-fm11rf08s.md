# Spec: phase 25.3 FM11RF08S key recovery

Status: implemented 2026-11-12; PN532 UART hardware validated, ACR122U not
recorded. Plan: [25-card-support.md](../plan/25-card-support.md).

## Problem

The previous FM11RF08S strategy only detected the static encrypted nonce
profile and returned `Unsupported`. The card's nested nonce is static, but its
clear value cannot be predicted from a first nonce with host-driven timing: a
reference distance measured on a known sector did not match the target sector,
and the resulting candidate set never contained the known key. PM3's
`--collect_fm11rf08s_without_backdoor` path relies on deterministic reader
timing that the supported transports do not expose.

The usable acquisition path is the published FM11RF08S backdoor: an
authentication command (`0x64` / `0x65`) with the backdoor key returns a nested
nonce that can be decrypted directly. This removes the timing prediction.

## Acquisition

- Backdoor keys, in PM3 order: `A396EFA4E24F`, `A31667A8CEC1`, `518B3354E760`.
- For one sector and one target key type, with no target key required:
  1. Select the card and enter recovery mode.
  2. Authenticate the sector block with the backdoor command and key.
  3. Send a nested backdoor authentication to the same block; decrypt the
     response with the backdoor key. This is the clear static nonce `nt`.
  4. Abort the nested exchange, reselect, and authenticate the backdoor again.
  5. Send a nested authentication with the target command (`0x60`/`0x61`) and
     capture the encrypted nonce `nt_enc` and its parity.
  6. Build `StaticSample { uid, nt, nt_enc, par_err }`.
- The backdoor command slot (`0x64` or `0x65`) and each key are tried until the
  card answers.
- Acquisition is read-only. No block or trailer is written.

## Solver

`staticnested::candidates` is a Rust port of PM3
`tools/mfc/card_only/staticnested_1nt.c`:

- `ks1 = nt ^ nt_enc`; `lfsr_recovery32(ks1, nt ^ uid)`.
- Roll back the authentication word, extract the 48-bit key, reinitialize the
  cipher, and filter with the last parity bit of the encrypted nonce.
- The candidate list is not trusted until each key authenticates the target
  block and reads its sector.

## Recovery flow

For every sector and key type:

1. Try every key already recovered and every candidate supplied by the caller
   (common keys, key store, CLI `--key`). Reused keys are common and skip the
   solver.
2. Otherwise collect a backdoor sample and generate candidates.
3. Verify candidates online. Every 1024 candidates emits a `BruteForce`
   progress event; cancellation is checked before each attempt.
4. Verify every recovered sector with a real authentication and block reads.
5. Return `sector_keys`, unique `keys`, `AttackKind::Fm11rf08s`, and a
   `StaticEncrypted` profile.

`auto` routes a detected static encrypted nonce to the same attack. The
without-backdoor distance prediction is not used.

## Limits

- One-nonce solver output was about 60,000 candidates for the test card.
  Online verification per unknown key can take minutes. The 2x1nt cross-filter
  is not implemented yet; reused keys avoid most of the cost on typical cards.
- A card without a working backdoor returns an explicit `Unsupported` error.
- The backdoor acquisition is FM11RF08S-specific. It does not claim FM11RF32N
  or other Fudan parts.
- No write, unlock, or key-change path is added.

## Acceptance

- The backdoor sample's clear nonce equals the value obtained by decrypting the
  target nonce with a known key.
- The solver candidate set contains that known key.
- `nfctl recover fm11rf08s` recovers 32/32 sector keys on the owned card and
  read-verifies 16/16 sectors.
- The attack performs no card write.
- ACR122U remains unrecorded until the same test runs on that reader.
