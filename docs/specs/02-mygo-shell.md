# Spec 02: MyGo shell and service boundary

## Goal

Replace Wails with the MyGo native UI without changing NFC behaviour. The
application services and DTOs stay the single source of state; the desktop
package becomes a presentation-only shell that calls them directly.

The shell follows the reviewed workbench design in
[`docs/design/02-workbench-ndef.png`](../design/02-workbench-ndef.png) and
[`docs/design/02-workbench-ndef.html`](../design/02-workbench-ndef.html):

- one workbench with a top context bar, left reader/card rail, center
  card-family workspace, right inspector/activity panel, and bottom action bar;
- reader discovery and connect/disconnect;
- card facts from the device manager;
- capability-driven tabs: Classic uses Blocks / Keys / Details; Type 2 uses
  Memory / NDEF / Protection / Details when Phase 05 lands;
- a Classic block table backed by the existing workbench snapshot, with a
  selected-block inspector;
- the persistent key catalog with add, delete, import, and export;
- a persistent task log fed by the application event stream;
- English and Simplified Chinese catalogues with a runtime language switch.

The previous five-page sidebar shell is superseded. The NDEF tab in the mockup
is a design target for Phase 05; Phase 02 must not display fake NDEF records.

## Non-goals

- No new card family, protocol, or write workflow.
- No `nfctl` CLI (Phase 03).
- No Wails feature parity beyond the initial workflow.
- No telemetry, update service, website, or account system.
- No Windows or macOS packaging.
- No card emulation.

## Affected packages and interfaces

### `app`

- `EventEmitter` remains the only application-to-UI event contract.
- `Bindings` becomes a UI-agnostic facade; update/telemetry methods are
  removed together with the corresponding services.
- `FileDialogs` is exported so the desktop shell injects MyGo dialogs.
- User-scoped files move from the old `NFCX` directory to `NFC Foundry`.
- Event channel names move from `nfcx:*` to `nfc-foundry:*`.

### `internal/desktop`

- Owns the MyGo `Application`, window, menus, native dialogs, and the
  view-model.
- Implements `app.EventEmitter` and applies events through `Window.Update`.
- Defines a narrow `Backend` interface implemented by `app.Bindings` so the
  view can be exercised with a fake in tests.
- Renders the workbench regions from the mockup: persistent left rail,
  capability-driven center tabs, right inspector/activity, and bottom actions.

### `locales`

- `locales/en.json` is the source catalogue.
- `locales/zh-Hans.json` is the complete translation.
- `locales/catalog_gen.go` is generated by `go tool mygo generate` and is
  committed.

### Build and packaging

- Root `main.go` starts the MyGo application directly; no embedded assets.
- `go.mod` pins MyGo instead of Wails and carries the CLI as a Go tool.
- The Makefile builds the native GUI and keeps the hardware-free test target.
- CI runs `go test ./...`, `go vet ./...`, the UI smoke test, and
  `reuse lint` on Arch Linux.
- The CGO shim links `libnfc-ng` through `pkg-config libnfc-ng` and the
  `libnfcng.so.6` identity.

## Capabilities and safety

No capability is added. The shell only exposes existing service calls:

- reader enumeration and exact connstring selection;
- card selection and read-only facts;
- full-card Classic read through the existing dump/restore pipeline;
- key catalog mutations, which persist with mode `0600`.

No write, UID, recovery, or configuration operation is exposed by this shell.
Reader ownership remains in the application device manager.

## Test plan

Hardware-free:

- `go test ./...` with the MyGo tester driving the shell view.
- The smoke test starts with fake DTOs, switches workbench tabs, refreshes
  readers, opens card facts, and checks the Classic and key views in both
  languages.
- `go vet ./...`, `reuse lint`, and `go tool mygo i18n check`.
- `go build` without the `libnfc` tag.
- The shell starts under headless mutter and exposes the workbench regions
  through AT-SPI; a visual review compares it with the mockup.

Hardware gate (manual, not CI):

- start the GUI against a PN532 UART reader;
- enumerate and connect the reader;
- place a MIFARE Classic card;
- confirm UID/ATQA/SAK and read the card into the block table;
- verify the sector-grouped block table, selected-block inspector, and key
  catalog;
- verify activity and inspector remain visible during the read.

## Packaging and license impact

- Remove `wails.json`, the HTML/TypeScript frontend, and Wails-only scripts.
- MyGo stays MIT; its license is already listed in `THIRD_PARTY_NOTICES.md`.
- `libnfc-ng` remains LGPL-3.0-or-later and dynamically linked.
- No new runtime dependency beyond MyGo's native Linux libraries.

## Rollback

The change is ordinary code and packaging. Reverting it restores the Wails
shell; no card or reader state is migrated. User files written under
`NFC Foundry` are new and can be moved manually if the shell is reverted.
