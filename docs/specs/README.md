# Implementation specs

One spec per change. A spec must be written before implementation and must
state:

- goal and non-goals;
- affected packages and interfaces;
- card/reader capabilities and safety rules;
- test plan, including hardware gates;
- packaging/license impact;
- rollback or failure handling.

Naming: `NN-short-title.md`, where `NN` matches the plan phase or a
feature-specific number. Keep specs short enough to review in one sitting.

Do not treat old NFCX specs as current; they are archived under
`../archive/nfcx-upstream/specs/`.
