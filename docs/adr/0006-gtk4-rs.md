# ADR 0006: GTK4-rs is the GUI stack

- Status: accepted
- Date: 2026-11-11
- Supersedes: [ADR 0005](0005-gpui-kit.md)

## Context

The GPUI Kit shell was removed on `feat/gtk4-ui`. The product needs one native
Linux desktop frontend with tables, dialogs, focus handling, overlays,
bilingual text, and an installable application icon and desktop entry. The
workbench is already implemented as a GTK4 application in `crates/gui`, and
the domain and CLI layers are unchanged.

## Decision

- Use **GTK4-rs** as the only GUI toolkit:
  - `gtk4` 0.11 with the `v4_10` feature;
  - `libadwaita` 0.9 with the `v1_5` feature.
- One GUI binary, `nfc-foundry`, built from `crates/gui`.
- GUI code is presentation only. Card and file operations call `nfc-app`
  services; view code does not touch readers, USB, serial ports, or native
  pointers.
- Reader work runs on a worker thread. Results return through `async-channel`
  to `glib::spawn_future_local`; GTK widgets are touched only on the main
  context.
- The workbench uses one window with a header, workspace selector, workspace
  tabs, a persistent reader/card rail, and a hidden System area opened from the
  header menu.
- UI tests run under Xvfb with `NFC_FOUNDRY_GUI_TESTS=1` and
  `GDK_BACKEND=x11`.

## Consequences

- ADR 0005 is superseded. GPUI Kit is not a fallback, and a second GUI
  frontend is not added.
- Linux is the current target. Windows/macOS assessment happens only after
  Linux feature parity; a future Windows build uses GTK and keeps GTK's look.
- Packaging depends on `gtk4`, `libadwaita`, and `hicolor-icon-theme`.
- The GPUI design rules and phase 18 implementation records remain historical
  references only.
