# Note: phase 25.3 FM11RF08S key recovery

Status: complete 2026-11-12 on PN532 UART; ACR122U not recorded. Plan:
[25-card-support.md](../plan/25-card-support.md). Spec:
[25c-fm11rf08s.md](../specs/25c-fm11rf08s.md).

## Card

- Fudan FM11RF08S, MIFARE Classic 1K compatible.
- UID `9C 81 95 D4`, ATQA `00 04`, SAK `08`.
- Reader: PN532 UART (CH340), `pn532_uart:/dev/ttyUSB0`, firmware 1.6.
- All sector keys were `FFFFFFFFFFFF`; the card is a tool-owned test card.

## Detection and backdoor sample

`recover fm11rf08s` reported the static encrypted nonce profile. The
without-backdoor reference-distance path was tested first: the measured
distance from a known-key nested nonce to its first nonce did not predict the
target clear nonce (the predicted value changed between runs), and its
candidate list did not contain the known key. The backdoor path was then used.

The hardware test collects one sample and checks both the clear nonce and the
solver candidate set:

```text
static sample uid=9C8195D4 nt=5B296CC7 nt_enc=A456DE20 par_err=0F candidates=59970
```

The backdoor clear nonce `5B296CC7` equals the value obtained by decrypting the
target `nt_enc` with the known target key. `FFFFFFFFFFFF` is present in the
59970-candidate list. The candidate count matches PM3's `staticnested_1nt` for
the same `uid/nt/nt_enc/par_err` vector.

## Full recovery

```sh
nfctl --device pn532_uart:/dev/ttyUSB0 --yes recover fm11rf08s
```

Result:

```text
strategy: [Fm11rf08s]
FM11RF08S backdoor · sector keys 32/32 · read verification 16/16 sectors
captured 32 recovered key(s) in ~/.config/nfc-foundry/classic-keys.json
```

The run used the supplied/common key for sector 0 and reused it for every
sector, which is correct for this card. The backdoor acquisition and solver are
covered by the hardware test above; the full attack's candidate-verification
loop is shared with the solver path.

No block, trailer, key, or lock was written. The card dump before and after
recovery was not required because the attack only authenticates and reads.

## Implementation

- `acquire::MIFARE_BACKDOOR_A/B`, custom command authentication, and
  `nested_nonce_command`.
- `staticnested::collect_sample_backdoor`, `rewind_nonce`, and a Rust port of
  the one-nonce candidate generator.
- `fm11rf08s_attack` now tries reused/supplied keys, collects backdoor samples,
  verifies candidates with `BruteForce` progress and cancellation, then
  read-verifies every sector.
- `auto` routes a static encrypted profile to the new attack.
- The diagnostic CLI and GTK progress surface are the existing recovery
  surfaces; no new command is added.

## Remaining

- ACR122U backdoor acquisition and recovery have not run on hardware.
- The 2x1nt cross-filter is not implemented; an unknown key can require about
  60,000 online authentication attempts.
- The without-backdoor distance path remains unreliable on host-driven
  transports and is not advertised.
