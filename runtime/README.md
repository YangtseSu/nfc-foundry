# Native runtime layout

Native runtime files are generated by `scripts/toolchain/` on Linux and are
not committed to Git. The supported layout is:

```text
runtime/linux-amd64/
  libnfcng.so.6.0.0
  libnfcng.so.6 -> libnfcng.so.6.0.0
  libnfcng.so -> libnfcng.so.6
  source.lock
  mfoc
  mfoc-source.lock
  mfcuk
  mfcuk-source.lock
  mfoc-hardnested
  mfoc-hardnested-source.lock
  nfcx-fake-engine        (development fixture only)
  LICENSES/
    libnfc-ng-COPYING.txt
    mfoc-COPYING.txt
    mfcuk-COPYING.txt
    mfoc-hardnested-COPYING.txt
```

Development headers and pkg-config metadata are generated separately under
`build/toolchain/linux-amd64/sdk`.

External engines use the same platform directory. NFC Foundry resolves fixed
logical engine names inside an application-controlled directory; the GUI
cannot provide an executable path. Release packages bundle pinned, licensed
engine builds instead of downloading them at runtime.

Build the pinned runtime pieces with:

```sh
make libnfc-ng-build
make mfoc-build
make mfcuk-build
make hardnested-build
```

Release packages also contain `manifest.json` and per-file SHA-256 values,
written by `make release-manifest`.

For framework testing, `make external-engine-fixture` adds `nfcx-fake-engine`
to the current runtime; it is ignored by Git and must not be included in
release packages.
